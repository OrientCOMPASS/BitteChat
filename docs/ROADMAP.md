## 二、现状快照（v0.5.29）

- 平台：Android（arm64 / x86_64）；核心 Rust 跨平台、UI Flutter
- 同步：swarm ext 直推 + DHT 头轮询/抓取泵 + 周期 swarm solicit（DHT 无关兜底）
- CI：全轮 warm ~7min；emulator 门禁（源码哈希未变跳过）；截图产物随 run 上传
- 已知边界：自发附件源文件被删/移后回退为 BT 卡片（就地做种决策）；个别网络环境
  DHT get 静默失败（0.5.28 诊断已布点，待真机日志定位根因）

## 三、路线图

### 短期（近 1–3 轮）
- [ ] 群聊同步 DHT 失效根因定位：依 0.5.28 诊断日志（poll/fetch/backoff/心跳）判定
      DHT get 无响应 vs 退避抑制 vs 线程异常；必要时增加 DHT 引导节点可配置/ swarm-only 降级开关
- [ ] 双实例模拟器测试：发送/接收两 emulator 实例互联，覆盖接收路径（下载→预览→已读）
      与 DM 握手，补足单实例无法验证的半区
- [ ] 通知与后台同步：Android 前台服务 + 轮询策略（功耗评估入 CI 报告）
- [ ] 会话内搜索与按日期跳转（纸带列表索引已具备自底向上估算基础）

### 中期
- [ ] 群治理：管理员/禁言/公告（系统消息 kind 扩展，DAG 兼容）
- [ ] 消息反应（emoji）与编辑标记（协议版本化 + 旧节点兼容规则）
- [ ] 多设备同身份（身份密钥同步 + 每设备头指针合并）
- [ ] 包体与启动优化：libmpv 动态化评估、baseline profile、启动路径裁剪
- [ ] iOS / 桌面移植评估（core 已跨平台；媒体后端与文件选择适配层）

### 长期
- [ ] 协议演进：群消息前向保密评估（现群聊为签名公开账本、DM 为 E2E）、
      后量子签名算法调研
- [ ] 受限网络连通性：中继/打洞回退层（swarm 不可达时的兜底传输）
- [ ] 反垃圾与邀请经济（PoW 邀请、tracker 公信列表治理）

### 设计边界（非目标）
- 中心服务器、账号体系、云端历史
- 群聊无条件端到端加密（群聊定位＝可哈希链验证的公开账本；私密沟通走 DM E2E）

## 四、流程约定
- 每轮：修改 → 对应模拟器测试 → CI 全绿 → 版本步进 0.0.1 → tag 发版 → 交付清单
- 历史条目只增不改；凝练版与 tag 一一对应，细节以 git log 为准
